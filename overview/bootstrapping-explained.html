Knowledge Bootstrapping — 해설판

사람이 쓴 분석 문서와 당시 데이터로 에이전트의 지식 베이스를 처음 채우는 흐름. 각 상자의 첫 줄은 전문 용어, 둘째 줄은 하는 일, 셋째 줄은 쉬운 비유다.

비유의 틀: 에이전트는 신입, 분석 문서는 선배의 풀이 노트, 지식 베이스는 공식 업무 노트, 평가는 모의고사.

원본 자료 지식 (Knowledge Base) 검증 · 평가 기록 · 추적

왜 이 순서인가

왼쪽 길 = 배우는 길

풀이 노트에서 요령을 뽑고(②), 그 요령이 맞는지 검산한 뒤(③), 통과한 것만 공식 노트에 올린다(④). 검산 없이 올리면 틀린 요령이 섞인다.

오른쪽 길 = 시험 보는 길

처음 보는 문제로 시험을 봐야 진짜 실력을 안다. 공부한 문제로 시험을 보면 외운 답을 맞히는 것뿐이다. 그래서 처음부터 두 묶음으로 나눈다.

아래 = 오답 노트

틀린 이유를 기록해 두면 다음에 비슷한 문제가 생겼을 때 먼저 찾아본다. 지난번에 어려웠던 "무엇을 왜 고쳤는지 추적"이 여기서 해결된다.

용어 해설

다이어그램과 구조 문서에 나오는 용어를 쉬운 말로 풀었다.

용어뜻비유
Knowledge Item (KI)지식 한 가지를 담은 짧은 문서 파일 하나업무 노트의 한 항목
Draft / Validated / DeprecatedKI의 상태. 초안 / 근거가 확인됨 / 더 이상 쓰지 않음메모 / 공식 노트 등재 / 줄 그어 지운 항목
Capture원본 자료를 손대지 않고 보관자료 모으기
Distill원본에서 핵심 지식만 뽑아 KI로 정리긴 풀이에서 요령만 추리기
Reverse Analysis (역분석)결과물(분석 문서)을 보고 거꾸로 과정을 추적완성된 요리를 보고 레시피 알아내기
Decision Heuristic"이 상황이면 이 데이터를 보고 이 기준으로 판단한다"는 규칙숙련자의 감각을 글로 적은 것
Query Pattern어떤 목적일 때 데이터를 어떻게 조회하는지 정리한 방법자료실에서 원하는 서류 찾는 법
Data Caveat데이터를 볼 때 조심할 점 (단위, 중복, 시점 차이 등)"이 표는 환불이 빠져 있음" 같은 주의 메모
Validate뽑은 지식이 맞는지 확인검산
Replay (재현 검증)정리한 방법으로 다시 해 봤을 때 원래 문서의 수치가 나오는지 확인같은 재료로 다시 만들어 같은 맛이 나는지 보기
Promote검증을 통과한 KI를 정식 등록공식 노트에 올리기
Serve필요한 상황에 맞는 KI를 에이전트에게 제공필요한 페이지만 펼쳐 주기
Hold-out 세트지식 추출에 쓰지 않고 평가용으로만 남겨 둔 케이스답을 안 본 실전 문제
Eval Case평가 문제 한 건. 입력과 기대 결과로 구성시험 문제 + 모범 답안
Eval SuiteEval Case 묶음시험지
Blind 평가정답 문서를 보여 주지 않고 평가오픈북이 아닌 시험
Baseline변경 전후를 비교할 기준 점수첫 모의고사 점수
Regression전에 되던 것이 변경 후 안 되게 되는 현상새 단원을 공부했더니 앞 단원을 틀리는 것
Eval Gate평가 점수가 기준에 못 미치면 변경을 막는 관문합격선
Issue (ISS)발견된 실패 사례 한 건틀린 문제
Change Record (CHG)변경 한 건의 기록: 계기, 가설, 바꾼 것, 전후 점수"왜 무엇을 고쳤고 점수가 어떻게 됐나" 한 장
Lessons Learned변경 과정에서 배운 점을 정리한 KI오답 노트의 교훈
Failure Mode반복해서 나타나는 실패 유형자주 하는 실수 유형
Traceability이슈 → 평가 → 변경 → 지식을 서로 따라갈 수 있는 성질영수증처럼 근거를 거슬러 올라갈 수 있음
